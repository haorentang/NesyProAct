Conventional skill induction stores skills as opaque action scripts and assumes they execute as intended. NesyProAct represents each skill with typed actions, grounding queries, pre-conditions, post-action verifiers and termination criteria, so every step is checked on the live page.

Abstract

Web-based language agents operate under severe partial observability, where the semantic divergence between internal state assumptions and the ground-truth environment is often unobservable. Consequently, agents frequently maintain high-level reasoning coherence over misgrounded states, causing errors to compound as subsequent decisions are conditioned on silently invalidated premises. We present NesyProAct, a proactive neural-symbolic agentic decision framework that transforms conventional ReAct-style web agents from reactive prompting pipelines into execution-aware decision processes. NesyProAct exposes a typed symbolic decision interface over states, actions, transitions, and subgoals, enabling LLM-based agents to automatically compose and reason over execution semantics across decision hierarchies. From this interface, programmatic verification logic is synthesized online to evaluate step-level executability and progress, with verification outcomes directly regulating decision evolution through targeted grounding interventions. As a result, execution feedback is integrated into planning itself, allowing agents to maintain semantic alignment under partial observability rather than propagating unverified assumptions. On WebArena, NesyProAct achieves a 12% overall improvement over the strong skill-induction framework ASI across six domains. NesyProAct also performs well with the small model GPT-4o-mini, with a 5.1% gain over ASI with Claude-3.5.

Four Layers of Grounding, Each Conditioning the Next

NesyProAct models web interaction as a Proactive Neural-Symbolic Agentic Decision Process (PNSDP): a POMDP extended with a hierarchical predicate space Φ, a verification operator 𝒱 and repair operators ℛ. Predicates are the vocabulary of checks the agent can compose. They are organized in four layers, and the decision made at each layer determines what the layer below perceives and verifies.

Decomposition

Turns the task into subgoal intents with their dependencies.

search "camera" → sort by price → add to cart

Transition

Compiles an intent into a typed action–query program.

type(q1,"camera"); click(q2)

State

Retrieves the focused elements that satisfy each query, with local context.

IS(InputBox) AND CONTAINS(placeholder,"search")

Action

Checks that the action is executable, runs it, and checks its effect.

editable(1051) → CONTAINS(1051,"camera")

Examples follow the task "Add the cheapest camera to the cart".

Verification is synthesized from the predicates as executable code, not delegated to an LLM judge. A violation is handled at the layer where it occurs, before any later step builds on the wrong state.

Skills Carry Their Own Verification Contract

A successful subgoal trajectory is distilled into a skill κ = (Preκ, ⟨(a1,q1), …, (aT,qT)⟩, Postκ): a symbolic matching condition, a program of typed actions paired with element-targeting queries, and a symbolic verifier.

LLM-free matching

A stored skill is selected by evaluating its pre-condition on the current page, with no LLM call.

Re-grounded, not replayed

Each step retrieves fresh elements that satisfy its query and runs only if the action-level check passes.

Verified outcome

The post-condition decides success by code. If a check fails, execution aborts or falls back to planning.

One Wrong Page, Five Confident Steps

GitLab task: "Please invite Vinta to the repo 'dotfiles' as a guest."

ReAct

  1. click("Do it myself") lands on the wrong repository
  2. click("Invite members")
  3. fill("Usernames", "Vinta")
  4. click("Vinta") invited to the wrong repository
  5. Reports "Vinta has already been invited as a Guest."

Nothing checks where step 1 led, so the error compounds silently.

NesyProAct

  1. Navigate toward the repository. The post-condition url_contains("dotfiles") is False, and the failure signal names this predicate.
  2. The repair operator re-plans the navigation and reaches the correct repository.
  3. url_contains("dotfiles") is now True; the agent proceeds to the invitation.

The error is caught at the step where it occurs.

Results on WebArena

We evaluate on the 812 WebArena tasks across six domains. With GPT-4o, NesyProAct reaches 58.2% average success and leads every compared method in every domain. With the same Claude-3.5-Sonnet backbone it exceeds ASI by 12.0 points, and with GPT-4o-mini it still outperforms every compared baseline that uses GPT-4o.
